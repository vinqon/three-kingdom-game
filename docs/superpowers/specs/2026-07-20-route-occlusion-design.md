# 城池静态坐标与连线清晰度规格

## 目标

修正地图中 A、B、C 三座城近似共线时 A—C 直连穿过 B 的问题。所有城市与路线组合均为固定数据，因此避让结果直接固化在城市坐标中，不在游戏运行时计算几何关系。

## 根因

路线由固定城市顺序和路线密度层级生成：精简模式连接相邻序号，标准模式增加闭环，密集模式增加跨一城的捷径。原坐标使庐江—长沙、建业—庐江、合肥—柴桑等固定路线与第三座城市重叠。

## 规则

- 城市坐标保存在 `CITY_DEFINITIONS`，游戏运行时只读取这些固定数值。
- 路线生成只按固定城市顺序、密度规则与边境路线表组装，再做无向去重。
- 固定坐标必须让九种地图组合中的每条路线与第三座城市保持至少 36 个 SVG 地图单位的净距；线段端点 8% 区域不计入穿越判断。
- 坐标调整在开发阶段一次性完成，校验逻辑只保留在测试中。

## 不变项

- 国内连接仍使用实线，跨国连接仍使用虚线，分类依据城市的 `originalOwner`。
- 首都之间不得直接连接。
- 每张地图必须保持全图连通。
- 三档连接的路线数量必须严格递增。
- 场景生成保持确定性，不使用随机数。
- AI、调兵和进攻继续读取同一份 `adjacentCityIds`，不增加只用于显示的虚假路线。

## 实现边界

- `src/game/scenario.ts` 不包含投影、距离计算或运行时路线切分。
- 地图渲染层继续忠实渲染场景中的邻接关系。
- 不引入曲线，也不手工维护九套独立路线表。

## 测试

- 对九种地图组合逐条检查：任一路线与任一非端点城市之间都不满足阻挡条件。
- 验证源代码不包含运行时几何切分函数，路线生成直接返回去重结果。
- 验证路线唯一、端点存在、邻接双向、全图连通、无首都直连。
- 验证精简、标准、密集的路线数量严格递增。
- 运行现有 AI、战斗、演出、构建和浏览器契约测试，确保游戏规则没有回归。
